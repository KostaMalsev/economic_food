# Revised empirical poverty thresholds — implementation plan

Date: 2026-09-28

Source: Limor's email **"משימות אחרונות, מעודכן"** dated 2026-09-28.

## Scope

Run the complete empirical analysis twice and keep the outputs separate:

1. Active households using `FoodNorm-active`.
2. Sedentary households using `FoodNorm-sedentary`.

Daniel's thresholds are comparison data only and are not inputs to these calculations.

## Small samples

For activity type `a` and household `i`:

- ZL sample: `abs(C3_actual_i - FoodNorm_a_i) / FoodNorm_a_i <= 10%`.
- ZU sample: `abs(Food_actual_i - FoodNorm_a_i) / FoodNorm_a_i <= 5%`.

Each sample is split by household size. Within each size, select the household
with the minimum `C3_actual / persons_count`; break ties by the smallest
household ID.

## Revised threshold calculation

The selected poorest household supplies only the non-food component:

`NonFood* = C32_actual + ... + C39_actual`.

For every qualifying household in the same size group, calculate:

`candidate threshold_i = FoodNorm_a_i + NonFood*`.

The published threshold is the mean of all candidate thresholds in that small
sample and household-size group:

`Z_t(a,n) = mean_i(FoodNorm_a_i + NonFood*(t,a,n))`, for `t in {L,U}`.

The audit output must retain the sample size, selected household ID, selected
household C3 per person, selected non-food expenditure, mean FoodNorm, and final
threshold.

## Revised nutritional-poverty definition

Primary definition used in graphs 2–5:

`Food_actual < FoodNorm` **and** `C3_actual < ZU`.

Sensitivity definition, saved separately:

`Food_actual < FoodNorm` **and** `C3_actual < 0.95 * ZU`.

The ZL and ZU poverty definitions remain `C3_actual < ZL` and
`C3_actual < ZU` respectively.

## Outputs for each activity type

1. FoodNorm, ZL and ZU by household size. Plot the threshold means and all
   candidate-threshold points from the two small samples.
2. Poverty rates by household size, with 95% Wilson intervals.
3. Overall poverty rates, with 95% Wilson intervals.
4. Mean poverty depth as a percentage among poor households.
5. FGT2 poverty severity, with non-poor households contributing zero.

Also save the small samples, threshold audit, assigned household data, graph
tables, and the `0.95 * ZU` sensitivity tables as CSV files.

## Website handoff

The existing Weebly calculator continues to calculate active and sedentary
FoodNorm and basket counts from the entered household members. ZL and ZU no
longer use regression coefficients. They are looked up by household size from
the empirical threshold table generated by this analysis. The handoff remains
a single script compatible with the existing result placeholders:

`[foodNormActive]`, `[foodNormSed]`, `[basketsActive]`, `[basketsSed]`,
`[lowActive]`, `[lowSed]`, `[highActive]`, `[highSed]`.

The supported household-size range is 1–9. An unsupported size must produce an
explicit error rather than silently extrapolating.

## Validation gates

- Both FoodNorm columns must map one-to-one to all 9,017 household IDs.
- C30+C31 must reconcile to `food_actual`; C32–C39 must reconcile to
  `nonfood_actual`.
- Each threshold mean must equal `sample mean FoodNorm + selected non-food`.
- Assigned thresholds must be constant within activity type and household size.
- Primary nutritional-poverty counts cannot exceed either the count below
  FoodNorm or the count below ZU.
- The `0.95 * ZU` sensitivity count cannot exceed the primary count.
- Active and sedentary outputs must be stored in separate directories.
